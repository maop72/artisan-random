# ArtisanRandom

Hardware-independent BIP39 seed generation for Bitcoin

Miguel Ortuño, August 2026

## Objective

ArtisanRandom is a procedure and tool to easily and verifiably
generate BIP39 recovery phrases independently of the hardware
wallet's random number generator that will subsequently be used
to store or manage the wallet.

ArtisanRandom is designed to prevent a flaw or vulnerability in a
hardware wallet's random number generator from compromising the
seeds generated by the device. In particular, this design avoids
issues such as the one suffered by Coinkite in August 2026, in
which a randomness generation bug affected the security of
generated keys.

ArtisanRandom prioritizes simplicity and ease of use over
achieving theoretical maximum entropy.

## Operating Principle

A 24-word BIP39 phrase contains 256 bits of entropy and 8
checksum bits, forming a total of 264 bits divided into 24 groups
of 11 bits. The first 23 words are determined from 23
independent, randomly generated values between 0 and 1999.

The final word contains 3 bits of random entropy and 8 checksum
bits calculated from all preceding entropy.

Therefore, strictly speaking, it would be necessary to generate
values between `0` and `2047`, since there are exactly 2048
possible values:

    2^11 = 2048

ArtisanRandom intentionally uses a slightly smaller range: values
between `0` and `1999`. The reason is simplicity. Manually
generating a number between `0000` and `1999` is significantly
easier than manually generating a uniform number between `0` and
`2047`.

This simplification incurs a very small entropy loss:

    log2(2048) = 11 bits
    log2(2000) ≈ 10.966 bits

The loss is approximately 0.0342 bits per number.

Each number has 2000 possible outcomes, giving a maximum entropy
of log2(2000) ≈ 10.966 bits. The effective entropy will depend on
the quality and unpredictability of the physical source used.

The total loss is therefore approximately 0.79 bits relative to
the 256 bits of entropy in a 24-word BIP39 seed. ArtisanRandom
deliberately accepts this minimal entropy loss in exchange for a
massive improvement in the simplicity of the manual process.

The algorithm, source code, BIP39 word list, and conversion
procedure can be completely public. None of these elements
constitute a secret. The security of the seed depends exclusively
on the unpredictability of the input values.

## Manual Entropy Generation

The user must manually generate 23 numbers between `0000` and
`1999`. In all proposed methods, each number is obtained in two
steps:

1.  Generate a first digit that is either `0` or `1`.
2.  Generate three additional digits, each between `0` and `9`.

Therefore, each result always consists of four digits and is
between `0000` and `1999`.

## Proposed Manual Methods

Below are several procedures for generating the first 23 words of
the BIP39 phrase using different physical sources.

These procedures can be combined with each other and with other
similar methods. This list is not exhaustive. Any simple
procedure that yields a reasonably unpredictable first digit
between `0` and `1` and three digits between `0` and `9` can be
used.

The 23 numbers do not have to be distinct. Repeated values are
valid as long as each occurrence was generated independently.

Procedures where the user can consciously choose the outcome must
be avoided, as human choices are not a reliable source of
randomness.

### Vehicle License Plates

This method uses vehicle license plates as the source for the
four digits. For each number:

1.  Choose a vehicle license plate using a procedure that does
    not allow consciously selecting or rejecting any number.
2.  Ignore letters.
3.  Use the first digit to generate `0` or `1`:
    - even digit → `0`;
    - odd digit → `1`.
4.  Use the next three digits directly.

For example:

    License plate: 4827 ABC

    4 is even → 0
    827 → kept

    Result: 0827

Another example:

    License plate: 7314 XYZ

    7 is odd → 1
    314 → kept

    Result: 1314

Repeat the procedure until 23 numbers are obtained.

### Coin and Ten-Sided Die

Use a coin to generate the first digit:

    heads → 0
    tails → 1

Then use a ten-sided die to generate each of the three remaining
digits.

For example:

    Coin: tails → 1
    Die: 4
    Die: 8
    Die: 2

    Result: 1482

### Coin and Ten-Value Deck of Cards

Use a coin to generate the first digit:

    heads → 0
    tails → 1

Then use a deck providing ten possible values and draw cards at
random to generate each of the three remaining digits.

For example:

    Coin: heads → 0
    Card: 7
    Card: 3
    Card: 9

    Result: 0739

### Books and Other Physical Sources

Everyday objects that provide unpredictable digits can also be
used.

For example, you can open a book randomly and use the last digit
of the page number.

## BIP39 Dictionary

ArtisanRandom uses the official English BIP39 list, consisting of
2048 words ordered according to the BIP39 specification.

Each group of 11 bits is used as an index into this list:

    0     → first word
    1     → second word
    ...
    2047  → last word

Keeping the dictionary separate from the program allows
independent auditing of the algorithm and the word list.

Note that the official BIP39 dictionary follows a different
convention, starting numbering from 1. ArtisanRandom starts
numbering from 0.

## BIP39 Dictionary File

By default, the dictionary is stored in the file `bip39.txt`.
This name can be changed using the `-w` or `--wordlist`
command-line option.

The file must contain all 2048 words in the order established by
BIP39, one per line.

To facilitate manual verification of generated words, each word
may be preceded by its index number followed by a space or tab.
For example:

    0000    abandon
    0001    ability
    0002    able
    0003    about
    0004    above

The program must ignore the index number and the space or tab
separating it from the word.

## Input File

The 23 numbers are saved in a text file, one per line.

By default, the file is named `numbers.txt`. This name can be
changed from the command line using `-i` or `--input`.

Example:

    0827
    1314
    0472
    1893
    0061
    ...
    1547

There must be exactly 23 lines.

Leading zeros are part of the representation of the number and
must be preserved, although they do not affect its numerical
value.

The input file contains no BIP39 words or any other data derived
from the seed.

## ArtisanRandom Program

The program must:

1.  Read and validate the 23 numbers.

    1.1. Read values from the input file.

    1.2. Verify that there are exactly 23 values.

    1.3. Verify that each value consists of four digits and is
    between `0000` and `1999`.

2.  Obtain the first 23 words.

    2.1. Look up each number in the BIP39 table.

    2.2. Retrieve the corresponding word for each number.

3.  Generate the final BIP39 word.

    3.1. Generate 3 additional bits of entropy using a
    cryptographically secure generator provided by the operating
    system.

    3.2. Combine the 23 numbers and the 3 additional bits to form
    the 256 bits of entropy.

    3.3. Compute the SHA-256 hash of the 256 entropy bits.

    3.4. Take the first 8 bits of the hash as the checksum.

    3.5. Concatenate the 3 entropy bits and 8 checksum bits to
    form the 11 bits that determine the final BIP39 word.

    3.6. Look up the BIP39 table and retrieve the corresponding
    word.

4.  Display the recovery phrase.

    4.1. Display the 24 BIP39 words in order, prefixed with their
    index number (starting from 1) to facilitate handling and
    verification.

The program requires no external dependencies and must
exclusively use Python's standard library.

## Generation of the Remaining 3 Bits

The 3 entropy bits required to complete the 256 bits are
automatically generated by ArtisanRandom using a
cryptographically secure generator provided by the operating
system, relying solely on the Python standard library.

These 3 bits are incorporated into the 253 bits obtained from the
23 numbers to form the full 256-bit BIP39 seed entropy.

## Independence from Hardware Wallets

ArtisanRandom generates entropy before the hardware wallet is
involved; the hardware wallet plays no role in generating the
seed. This avoids dependence on:

- the manufacturer's random number generator;
- the specific firmware implementation;
- potential entropy generation bugs in the device;
- future vulnerabilities discovered in the hardware wallet's RNG.

A seed generated with ArtisanRandom can subsequently be imported
into any hardware wallet that supports importing an existing
BIP39 seed phrase.

## Physical Security

- Generation must take place in a private environment.

- The file containing the 23 numbers must be treated as sensitive
  data while generating or recovering the seed.

- The resulting seed phrase must never be entered into a web page
  or online service.

- The program must be fully executable without an internet
  connection.

## Simplicity and Auditability

- ArtisanRandom keeps the codebase deliberately minimal.

- It does not aim to build a general cryptographic library or
  full BIP39 implementation.

- The code must be simple enough for anyone with basic
  programming knowledge to read and fully understand its
  behavior. Even without Python expertise, straightforward code
  must be used, avoiding language-specific features.

- The absence of external dependencies is a key requirement.

- Reliance on the software is restricted to simple,
  well-understood operations:

  - reading and validating numbers;
  - generating three random bits;
  - binary/bitwise operations;
  - SHA-256 calculation;
  - BIP39 word list lookup.
